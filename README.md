# webp.datatype

A WebP picture datatype for AmigaOS 3.x (68020+), based on Google's
[libwebp](https://chromium.googlesource.com/webm/libwebp) decoder.

- lossy (VP8) and lossless (VP8L) WebP
- alpha channel (32-bit picture with `mskHasAlpha`)
- animated WebP: first frame is shown
- 24-bit output; on 8-bit and lower screens, **picture.datatype** does the
  remapping/dithering (V43+ / V45 / V47 picture.datatype), exactly like for
  PNG or JPEG datatypes. Needs picture.datatype v43 or higher.

## How it works

A datatype is a BOOPSI class library, subclass of `picture.datatype`:

```
datatypes.library --(descriptor DEVS:DataTypes/WebP matches "RIFF????WEBP")-->
  opens SYS:Classes/DataTypes/webp.datatype, calls ObtainEngine() (-30)
  --> NewObject(webp class) --> OM_NEW: picture.datatype creates the object,
      webp.datatype decodes the file and hands over truecolor pixels.
```

Pixel hand-over, in `src/webpclass.c`:

1. **V47 picture.datatype**: `PDTA_ObtainPixelBuffer` gives direct access to
   picture.datatype's own buffer; libwebp decodes straight into it (no extra
   full-size copy).
2. **V43+**: decode into a temporary RGB/ARGB buffer, then one
   `PDTM_WRITEPIXELARRAY`.

Everything else (remap to screen, dithering, scaling, friend bitmaps, saving
as ILBM via `DTM_WRITE`/`DTWM_IFF`) is picture.datatype's job.

## Shared binary constraints

Like `utf8rastport.library` in EmojiGear, the class library can't use
`-shared` or libnix:

| file | role |
|---|---|
| `src/libinit.s` | RomTag, library vectors (Open/Close/Expunge/ObtainEngine), `__start` returning -1, and `WebpCallWithStack` (exec `StackSwap`) |
| `src/amiga_library.ld` | linker script: `__libinit` section first in the hunk |
| `src/libcinit.c` | `CLibInit`/`CLibExpunge`: open system libs + picture.datatype v43, `MakeClass`/`AddClass`, libwebp dsp init |
| `src/lib_amiga_crt.c` | reentrant mini CRT: malloc/calloc/realloc/free on `AllocVec`, mem*, qsort, `__bcopz` |
| `src/softfloat_min.c` | the 4 soft-float helpers libwebp needs (libnix's use mathieee libs opened by its startup) |

Link: `-nostdlib -nostartfiles -Wl,-e,__start -T amiga_library.ld`, plus
libgcc `libm020` for 64-bit arithmetic.

Rules followed:

- **Globals**: only library bases, the class pointer, and libwebp's dsp
  function pointers. They're all written once in `CLibInit` (called from
  `LibOpen`, under Forbid). Every per-picture state is on the decoding task's
  stack or in its `AllocVec` memory, so several tasks can decode at once.
- **Stack**: datatype methods run on the caller's stack (maybe 4 KB). If
  less than 48 KB is free, the decode runs on a temporary stack via
  `StackSwap`.
- **Expunge**: refused while objects of the class are alive
  (`FreeClass` fails), and done via the delayed-expunge bit otherwise.

libwebp is compiled from the untouched `libwebp-main` tree. The decoder,
demux, dsp, and utils are built without SIMD and without threads, with
`WORDS_BIGENDIAN` defined. The one exception is `dsp/yuv.c`, which is
compiled from a copy generated at configure time with
`#define USE_GAMMA_COMPRESSION` removed. That gamma code is encoder-only and
needs `pow()` and double soft-float.

Linker `--gc-sections` does not work with the hunk linker. It doesn't follow
references out of the vasm object, so it strips everything.

## Build

Cross compiler: bebbo's m68k-amigaos-gcc 6.5 in `/opt/amiga`, with the cmake
platform from [amigacommonlibs](https://github.com/krabobmkd/amigacommonlibs).
You also need python3 on the host to generate the descriptor.

libwebp is not included in this repository. Clone it next to the sources
(it's git-ignored), or pass `-DWEBP_ROOT=/path/to/libwebp` to cmake:

```sh
git clone https://chromium.googlesource.com/webm/libwebp libwebp-main
mkdir buildAmiga && cd buildAmiga
cmake .. -DCMAKE_TOOLCHAIN_FILE=/home/krabob/Code/Amiga/amigacommonlibs/cmake/Modules/Platform/m68k-amigaos.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build .
cmake --build . --target dist     # -> buildAmiga/dist/WebPDT
cd dist && lha a WebPDT.lha WebPDT
```

Outputs in the build dir:

- `webp.datatype`: the class
- `WebP`: the descriptor, generated by `tools/mkdtdesc.py`. That script is a
  host replacement for DTDesc/createdtdesc, and its output was checked
  byte-identical to a descriptor made on Amiga.
- `webpdtinfo`: a CLI test tool
- `dist` target: also generates the project icons with `tools/mkicon.py`.
  `Install_WebPDT.info` runs `C:Installer`, and `Devs/DataTypes/WebP.info`
  runs `C:AddDataTypes`. Icons placed in `dist/` by hand override the
  generated ones.
- `webp.datatype.map`: the link map

The version is in `CMakeLists.txt` (`WEBPDT_VERSION`/`WEBPDT_REVISION`).
It's generated into `libversion.h` (C) and `libversion.i` (asm).

## Install

Run `Install_WebPDT` (Amiga Installer script). It asks once, copies
`webp.datatype` to `SYS:Classes/DataTypes/` and `WebP` (with its icon) to
`SYS:Devs/DataTypes/`, reports whether the copy worked, and asks you to
reboot.

The descriptor name "WebP" is shared by other WebP datatypes (e.g.
WarpWebP), so installing replaces theirs.

Manual install:

```
Copy webp.datatype SYS:Classes/DataTypes/
Copy WebP WebP.info SYS:Devs/DataTypes/
AddDataTypes DEVS:DataTypes/WebP REFRESH   ; or reboot
```

## Testing on the Amiga

```
webpdtinfo pic.webp                   ; loads through datatypes.library, prints size/depth
webpdtinfo pic.webp SAVE ram:pic.ilbm ; also checks pixels via DTM_WRITE (ILBM)
MultiView pic.webp
```

After replacing the binary: quit the apps that use it, then run `Avail FLUSH`
so the old copy is expunged, same as with the EmojiGear libs.
